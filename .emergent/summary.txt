<analysis>
The previous AI engineer successfully developed a Notion-style task manager, iteratively enhancing its functionality based on user feedback. Key phases included establishing core CRUD operations for tasks and projects, implementing a robust role-based authentication system, and adding advanced features like custom date tracking, flexible task creation, and admin user management. When a WebSocket real-time update approach failed due to infrastructure limitations, the engineer seamlessly pivoted to a polling-based system. Subsequently, comprehensive file attachment with inline viewing, a detailed subtask system with two-level nesting, and significant terminology refactoring to suit a lumberyard house building context were added. The engineer consistently delivered features, debugged issues, and performed testing, always adapting to explicit user requirements. The current focus is on refining the Ideas section.
</analysis>

<product_requirements>
The initial user request was for a Notion-style task manager, enabling CRUD operations on tasks, categories/priorities, and due dates, with a dashboard. This evolved significantly:
*   **Project-specific organization**: All tasks (later rooms) and ideas are nested under projects (later house building projects).
*   **Priority Levels**: High, Medium, Low with color coding.
*   **Views**: Calendar (with custom order/delivery dates, filtered by user's assigned projects for regular users), Task/Room list (with filtering/sorting), Ideas board.
*   **Editing**: Full edit capabilities for tasks/rooms, projects, and ideas.
*   **Flexible Creation**: Tasks/rooms can be created with minimal fields, with others filled later.
*   **User Authentication & Roles**: Secure login, Admin (full access, user management, create/assign users) and Regular User (view-only on assigned projects). Demo buttons removed.
*   **Real-time Updates**: Initially requested WebSockets, pivoted to polling for notifications on task/project creation, updates, and completion.
*   **Team Communication**: Messaging system for users to send messages to admins. Notifications can be turned off.
*   **File Attachments**: Upload photos/PDFs/other files to projects and tasks/rooms, with support for inline viewing of many file types.
*   **Subtasks**: Collapsible/expandable, 2-level nesting limit, auto-completion of parent task, optional order/delivery dates (no due date), file attachment support. Subtasks are color-coded based on their parent room.
*   **Lumberyard Context**: Projects renamed to House Building Projects and tasks to House Rooms, with associated UI and placeholder text changes to fit a construction workflow, ensuring rooms are specific to projects.
</product_requirements>

**Key Features Implemented:**
*   **Core Project & Room Management**: Users can create, view, edit, and delete House Building Projects and House Rooms. Rooms are specific to Projects with no overlap.
*   **Custom Dates**: Rooms and Subtasks support , , and . Subtasks only use  and , which are optional and can be filled later.
*   **Role-Based Authentication**: Secure login with distinct Admin and Regular User roles. Admins have full control, including comprehensive user management (create, assign projects, deactivate users). Regular users have view-only access to assigned projects/rooms.
*   **Polling-Based Real-time System**: Backend and frontend are configured for polling to deliver real-time notifications (e.g., New Task Created) and messages. The notification UI elements (bell, message icons, and toast notifications) are active, though notifications were recently requested to be turned off.
*   **Comprehensive File Attachment**: Users can drag-and-drop multiple file types (images, documents, archives, etc.) onto both projects and rooms. Files are stored and can be downloaded or viewed inline (PDFs, images, text, code files) directly within the browser using a modal viewer. Subtasks also support file attachments.
*   **Granular Subtask System**: Each House Room can have subtasks with a 2-level nesting limit. Subtasks are collapsible/expandable, display their progress (completed/total), and can auto-complete the parent room when all subtasks are done.
*   **Visual Enhancements**: Subtasks are now color-coded, inheriting the color of their parent House Room, with visual indicators like colored left borders, dot indicators, and matching checkbox borders. Date labels for subtasks (Order Date, Delivery Date) are explicitly shown and are optional.
*   **Ideas Board**: Initial ideas functionality exists, but the ability to edit and delete ideas is currently being implemented.
